# IFS Coatings Mexico

WordPress (Oxygen) → Astro static migration of https://ifscoatings.mx/.
The site is in **Spanish (es-MX)**.

The migration was a pixel-for-pixel port; as of September 2026 the site is
**deliberately restyled** to look contemporary, with **no content change**.
Read `docs/design-system.md` before touching styling. `npm run compare` is the
gate that proves no copy moved; `npm run verify:layout` compares against the old
design and is expected to fail.

Read `README.md` and `docs/content-map.md` first: they explain where content
comes from and why the styling is compiled rather than hand-written. Then
`.claude/skills/wp-migration/SKILL.md` for the migration rules.

**Deliberate differences from the old site are in `docs/deviations.md`** and are
encoded in `scripts/compare-content.mjs` (`EXPECTED`) and
`scripts/verify-layout.mjs` (`DEVIATIONS`). Add to both when accepting a new one,
so an accepted change never reads as a regression.

## Working constraints

- Never start or stop the dev server; ask the user to run `npm run dev`.
- No inline `style` attributes. Use a Tailwind utility or a class in
  `src/styles/theme.css`.
- `src/content.config.ts` and `public/admin/config.yml` change together.
- `src/content/` is generated by `scripts/extract-content.mjs` until go-live;
  never hand-edit it. Fix rendering in the loader or the templates.
- Run `npm run verify` and `npm run build` before committing.
- `wp-cache/` is the cached old site and the source for every script. It is
  git-ignored and re-fetchable only while the old host is up.
- Styling is **compiled**, not authored: `scripts/lib/css-to-tw.mjs` turns the
  old Oxygen declarations into Tailwind utilities. Fix visual bugs there or in
  the templates, never by hand-editing `src/content/`.

## Source site facts

| Fact | Value |
|---|---|
| Platform | WordPress 7.1, Oxygen Builder 4.9.7 |
| Content | 29 published pages, 1 post (`hello-world`, WP default — retire) |
| Custom post types | none |
| Page CSS | `/wp-content/uploads/oxygen/css/<postId>.css` + `universal.css` |
| Header/footer template | Oxygen post `6` (`css/6.css`) |
| Home | post `47` |
| Plugins that shape content | Formidable Forms, TablePress, Yoast SEO, SuperPWA |
| Fonts | Roboto, Noto Sans JP, Nunito Sans (Google Fonts) |

Oxygen stamps every rendered element with `id="<type>_<n>-<postId>"`, so a
per-page extraction recipe selects by post id. Oxygen output never passes
through `the_content`, so **content comes from the rendered front-end HTML**,
not the REST API body. The REST API is used only for ids, slugs, dates and
Yoast metadata.

## Language

The old site serves `lang="en-US"` and `og:locale=en_US` despite being entirely
in Spanish — a bug to fix, not replicate. The new site is `es-MX` in the html
lang attribute, Open Graph locale, and schema `inLanguage`.
